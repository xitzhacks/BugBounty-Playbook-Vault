# Bypassing Akamai / CDN Protection via Browser Automation

## Problem
Targets behind Akamai (or similar CDNs/WAFs) return 403/403 for all `curl`/terminal requests, blocking:
- WordPress endpoint probing (`/cms/wp-login.php`, `/cms/wp-admin/`)
- WordPress REST API (`/cms/wp-json/`)
- XML sitemaps (`/sitemap_index.xml`)
- RSS feeds (`/feed`)

## Solution
Use browser automation tools (`browser_navigate`) which bypass Akamai because browsers send normal visitor TLS fingerprints, headers, and JS execution context. Akamai's bot management blocks scripted curl but allows browser-based access.

### Workflow
1. **Try curl first** — if 403 with "Access Denied", confirm Akamai is blocking
2. **Use browser_navigate** to fetch the same URL — this bypasses Akamai bot detection
3. **Extract sitemaps** — the `sitemap_index.xml` reveals all sub-sitemaps (posts, authors, categories, tags, glossary)
4. **Cascade through sitemaps** — each sitemap reveals hundreds of URLs, author usernames, category names

### Real Case: fitbook.de
- `curl https://www.fitbook.de/` → 403 "Access Denied" (Akamai)
- `browser_navigate https://www.fitbook.de/sitemap_index.xml` → 200 with 27 sitemaps
- `browser_navigate https://www.fitbook.de/author-sitemap.xml` → 52 author usernames (user enumeration)
- `browser_navigate https://www.fitbook.de/category-sitemap.xml` → 16 category URLs
- `browser_navigate https://www.fitbook.de/post-sitemap.xml` → 501 article URLs
- `browser_navigate https://www.fitbook.de/feed` → WordPress RSS with `?p=` GUID format (confirms WordPress)

## Key Insight: Sitemaps as Feature Maps
XML sitemaps are goldmines for feature mapping:
- **post-sitemap.xml** — all article URLs (feature inventory)
- **author-sitemap.xml** — all author usernames (user enumeration)
- **category-sitemap.xml** — site structure (sections, special features)
- **post_tag-sitemap.xml** — tags reveal features (e.g., "Krebs", "Diabetes")
- **ms_advertorial-sitemap.xml** — sponsored/advertising content
- **glossary_cat-sitemap.xml** — medical/dictionary glossary
- **books_video-sitemap.xml** — video content section

### WordPress Confirmation via Sitemap
- **Yoast SEO** generates sitemaps (confirmed by "Generated by Yoast SEO" text)
- **WordPress RSS feed** uses `?p=ID` GUID format (WordPress native)
- **Author pages** at `/autor/{username}` (custom rewrite of `/author/{username}`)
- **Image CDN** at `cdn.book-family.de/fitbook/data/uploads/` (WordPress uploads path pattern)

## Browser-Based WordPress Probing
When Akamai blocks terminal access, use browser_navigate for:
- `/cms/wp-login.php` — check if login form renders
- `/cms/wp-admin/` — check if admin redirects to login
- `/cms/wp-json/` — check REST API responses
- `/cms/xmlrpc.php` — check XML-RPC status
- `/cms/readme.html` — WordPress version disclosure
- `/cms/.env` — environment file leakage

### Note: Akamai May Escalate
After initial browser-based access, Akamai may start blocking browser_navigate too (as happened with wp-login.php on fitbook.de). If this occurs, the browser-based approach is exhausted and alternative bypass methods should be attempted (residential proxies, different User-Agents, etc.).
