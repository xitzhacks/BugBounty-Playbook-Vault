# Firebase Email-Link Login ATO Chain (signInWithEmailLink)

## Why it exists
Firebase passwordless email-link login sends a magic link containing an
`oobCode` (action code). The link is generated by a backend proxy that takes
an `email` in the request. If the proxy does NOT bind that email to the
authenticated session, an attacker substitutes the victim's email and receives
a working login link for the victim's account.

## Flow under test (attacker = account A, victim = account B)
1. Attacker A logs in normally; captures `Authorization` header (Firebase ID
   token, or the app's session cookie) from any `/api/*` or `/auth/*` request.
2. A calls the email-link proxy with B's email:
   ```
   POST /auth/email/token
   Authorization: Bearer <A_TOKEN>
   {"email":"[REDACTED_EMAIL]", "returnUrl":"https://app/"}
   ```
   (Endpoint name varies: `/auth/email/token`, `/api/auth/email-link`,
   `/auth/email/link`. Find it in the JS bundles — grep `signInWithEmailLink`
   and the surrounding POST call.)
3. If the server returns 200 + an `oobCode`/`actionCode` for B's email, A opens
   the resulting link in A's browser and calls `signInWithEmailLink(email=B)`.
4. A is now authenticated AS B. Full ATO.

## Confirmation (OOB not needed — self-contained)
- The generated link's email == B's email (not A's). That's the proof the proxy
  trusted the request body.
- After step 4, A's session resolves to B's profile/uid.

## False-negative kill
- If 401/403 on the proxy -> email IS bound to session -> not vulnerable via this path.
- If proxy requires the email to match the session's verified email -> not vulnerable.

## Real case: winticket.jp
- Bundles contain `signInWithEmailLink`, `/v1/accounts:signInWithEmailLink`,
  and a `/auth/email/token` POST. Auth stack: Firebase + Google OAuth +
  reCAPTCHA + PayPay. API is an Istio/Envoy gateway (proxy-prefixed `/api/...`).
- Unauthenticated probing cannot test this — needs A's session token + B's email.
- Pairs with hunt-idor: the same `/my/*` object IDs are reachable once logged
  in as B, so email-link swap -> IDOR fan-out is the full chain.
